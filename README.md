# Spurs Pay docs

These docs exist so the UI is designed on purpose instead of generated by default. Read them before building or reviewing any screen in Phase 9.

| Doc | Read it when |
| --- | --- |
| [docs/product-spec.md](docs/product-spec.md) | You need to know what the app does, who it is for, the rules behind each flow, and what every error should do on screen |
| [docs/design-principles.md](docs/design-principles.md) | You are making a visual decision, or reviewing one. Includes the list of "AI tells" to avoid |
| [docs/design-system.md](docs/design-system.md) | You are writing a component. Tokens, type scale, spacing, radius, motion, component specs |
| [docs/screens.md](docs/screens.md) | You are building a specific screen. Wireframes, content, states |
| [docs/content-guidelines.md](docs/content-guidelines.md) | You are writing any text a user will read, including errors and notifications |
| [docs/ui-quality-checklist.md](docs/ui-quality-checklist.md) | A screen is "done" and needs review before merge |

## Rules for these docs

1. The docs are the source of truth. If the UI needs to differ, change the doc in the same pull request.
2. Where a doc states a number (limit, length, rate), it comes from code. The file is named next to it. If the code changes, update the553 doc.
3. Nothing here overrides `todo.md` ground rules: integer kobo, `AppError` codes, provider secrecy, no business logic in components.

## Phase 9 build order

Do these in order. Each step ends with the checklist in `ui-quality-checklist.md`.

1. **Foundations.** Add the extra tokens from `design-system.md` to `globals.css`. Add an icon set. Build the private UI kit page (`/dev/ui`, development only) that shows every component in light and dark.
2. **Core components.** Button (add `danger`), Input, ListRow, Avatar, Sheet, Dialog, Toast, Skeleton, StatusBadge, EmptyState, Banner, AmountDisplay.
3. **Shell.** Header, navigation (hide routes that are not built), desktop layout.
4. **Home.** Balance, actions, setup checklist, recent people, recent activity.
5. **Send flow.** Recipient, amount, review, PIN sheet, success, every failure state.
6. **Settings.** Tag, PIN, appearance, sign out. These unblock sending for new users, so build them before polishing.
7. **Add money.** Funding account details and copy.
8. **Activity and receipts.** Needs the Phase 8 activity API. Until it exists, Home shows the empty state only.
9. **Polish.** Accessibility pass, reduced motion, PWA manifest and icons, offline shell.

## Dependencies the UI is waiting on

- Phase 8 activity feed and receipt data. Without it, Home "Recent activity" and `/activity` cannot show real rows.
- A balance endpoint or server component read for the wallet. Home currently renders `formatNaira(0n)`.
- A profile read that returns tag and display name, so the setup checklist can know what is missing.
- A decision on PIN reset (see Open decisions in the product spec).
