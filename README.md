| Doc | Read it when |

## Rules for these docs

1. The docs are the source of truth. If the UI needs to differ, change the doc in the same pull request.
2. Where a doc states a number (limit, length, rate), it comes from code. The file is named next to it. If the code changes, update that doc.
3. Nothing here overrides `todo.md` ground rules: integer kobo, `AppError` codes, provider secrecy, no business logic in components.

## Checkout UI build order

Do these in order. Each step ends with the checklist in `ui-quality-checklist.md`.

1. **Foundations.** Add the extra tokens from `design-system.md` to `globals.css`. Add an icon set. Build the private UI kit page (`/dev/ui`, development only) that shows every component in light and dark.
2. **Core components.** Button (add `danger`), Input, ListRow, Avatar, Sheet, Dialog, Toast, Skeleton, StatusBadge, EmptyState, Banner, AmountDisplay.
3. **Shell.** Header, navigation (hide routes that are not built), collapsible desktop rail.
4. **Payment methods.** Wallet availability, tokenized saved cards, bank-transfer option.
5. **Home.** Payment-method summary, actionable setup requirements, recent payments.
6. **Checkout.** Private Spurs-product session, method selection, Wallet authorization, tokenized card, bank transfer, result states.
7. **Activity and receipts.** Checkout payments only; Wallet funding remains in Wallet activity.
8. **Settings.** Spurs Accounts profile link, appearance, sign out. Wallet PIN is owned by Wallet.
9. **Polish.** Accessibility pass, reduced motion, PWA manifest and icons, offline shell.

## Dependencies the UI is waiting on

- First-party checkout-session, payment-method, and transaction-status contracts.
- Wallet authorization and funding service contracts; do not read Wallet's database.
- A profile/verification read for actual checkout prerequisites. Do not use the legacy tag/PIN checklist.
- Decisions listed in section 13 of `docs/product-spec.md`, especially Wallet debit/PIN ownership and card tokenization.

## Internal admin API

The read-only `GET /api/internal/admin/stats` and
`GET /api/internal/admin/checkouts` endpoints provide Admin 2 with Pay user and
merchant totals, checkout status totals, and recent checkout metadata. They are
authenticated with the `x-internal-secret` header and rate-limited to 120 requests
per minute. Set `INTERNAL_SHARED_SECRET` to at least 32 random characters in Pay's
server environment, then set the same value as `PAY_INTERNAL_SECRET` in Admin 2.
Configure `PAY_API_URL` in Admin 2 to the Pay app origin. Do not expose either secret
to browser code or include it in source control.
